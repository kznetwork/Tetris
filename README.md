# Tetris MVP 구현 To-Do

이 문서는 [PRD.md](./PRD.md)를 기준으로 Tetris MVP를 완성하기 위한 작업 목록이다. 각 Task는 가능한 한 독립적으로 구현하고 검증할 수 있도록 나누었으며, 작업 간 의존성을 고려해 실행 순서대로 정렬했다.

| Task | 산출물 | 완료 기준 |
|---|---|---|
| 1. 브라우저 앱 기본 구조 생성 | 게임 페이지, 스타일 파일, JavaScript 진입점 | 데스크톱 브라우저에서 페이지가 오류 없이 열리고 게임 영역, 점수 영역, Restart 버튼이 표시된다. |
| 2. 테스트 실행 환경 구성 | 핵심 게임 로직용 테스트 디렉터리 및 실행 명령 | 샘플 테스트 1개가 통과하고, 한 명령으로 전체 테스트를 실행할 수 있다. 새 운영 의존성은 추가하지 않는다. |
| 3. 게임 상수와 상태 모델 정의 | 보드 크기, 빈 셀, 게임 상태 구조 | 보드 크기가 10 × 20으로 정의되고, 보드·현재 블록·점수·게임 종료 여부를 UI 없이 생성하고 조회할 수 있다. |
| 4. 빈 게임 보드 생성 | 10 × 20 보드 생성 함수와 단위 테스트 | 생성된 보드가 20행, 각 행이 10열이며 모든 셀이 빈 상태라는 테스트가 통과한다. 보드 인스턴스 간 행 배열이 공유되지 않는다. |
| 5. 7종 Tetromino 데이터 정의 | I, O, T, S, Z, J, L 모양 및 식별자 | 7종 블록이 모두 존재하고 각 블록이 정확히 4개의 셀로 구성된다는 테스트가 통과한다. |
| 6. Tetromino 생성 함수 구현 | 블록 종류, 좌표, 초기 위치를 가진 생성 함수 | 지정한 종류의 블록을 생성할 수 있고, 모든 종류가 보드 상단의 유효한 시작 위치에 배치된다는 테스트가 통과한다. |
| 7. 무작위 Tetromino 선택 구현 | 7종 중 다음 블록을 선택하는 함수 | 주입한 난수 값에 따라 예상한 블록이 선택되고, 반환값이 항상 7종 중 하나라는 테스트가 통과한다. |
| 8. 블록 셀 좌표 계산 구현 | 블록의 보드상 절대 셀 좌표 계산 함수 | 블록의 모양과 기준 위치로부터 4개 셀의 절대 좌표가 정확히 계산된다는 테스트가 통과한다. |
| 9. 보드 경계 충돌 감지 구현 | 좌우 벽과 바닥 경계 검사 함수 | 블록이 왼쪽·오른쪽 벽 또는 바닥을 벗어나면 충돌로 판정하고, 경계 안에서는 허용한다는 테스트가 통과한다. |
| 10. 고정 블록 충돌 감지 구현 | 보드의 점유 셀과 현재 블록 간 충돌 검사 | 빈 셀 이동은 허용되고 이미 채워진 셀과 겹치는 이동은 거부된다는 테스트가 통과한다. |
| 11. 좌우 이동 로직 구현 | 현재 블록을 한 칸 좌우로 이동하는 함수 | 충돌이 없을 때만 한 칸 이동하고, 벽이나 고정 블록과 충돌하는 경우 위치가 유지된다는 테스트가 통과한다. |
| 12. 회전 좌표 변환 구현 | Tetromino 회전 함수 | 회전 가능한 각 블록이 예상 좌표로 회전하고, O 블록은 회전해도 모양이 유지된다는 테스트가 통과한다. |
| 13. 충돌을 고려한 회전 적용 | 현재 위치에서 회전을 시도하는 함수 | 회전 후 유효한 위치일 때만 회전 상태가 변경되고, 벽·바닥·고정 블록과 겹치면 기존 상태가 유지된다는 테스트가 통과한다. |
| 14. 한 칸 하강 로직 구현 | 현재 블록의 하강 시도 함수 | 아래 공간이 비어 있으면 정확히 한 칸 내려가고, 충돌 직전에는 더 내려가지 않는다는 테스트가 통과한다. |
| 15. 블록 고정 로직 구현 | 현재 블록을 보드에 기록하는 함수 | 하강할 수 없는 블록의 4개 셀이 보드에 정확히 기록되고 기존 고정 셀이 손상되지 않는다는 테스트가 통과한다. |
| 16. 완성 라인 탐지 구현 | 가득 찬 행을 찾는 함수 | 빈 행, 일부만 찬 행, 한 개 및 여러 개의 완성 행을 정확히 구분한다는 테스트가 통과한다. |
| 17. 완성 라인 제거 구현 | 완성 행 제거 및 빈 행 보충 함수 | 완성된 모든 행이 제거되고 같은 수의 빈 행이 상단에 추가되며 보드 크기가 10 × 20으로 유지된다는 테스트가 통과한다. |
| 18. 점수 계산 규칙 구현 | 제거한 라인 수에 따른 점수 함수 | 0, 1, 2, 3, 4줄 제거 각각에 대해 정의된 점수가 반환되고 누적 점수가 정확히 증가한다는 테스트가 통과한다. |
| 19. 다음 블록 전환 흐름 구현 | 고정→라인 제거→점수 반영→새 블록 생성 로직 | 블록이 고정된 뒤 라인과 점수가 처리되고 새 블록이 생성되며, 처리 순서를 검증하는 통합 테스트가 통과한다. |
| 20. Game Over 판정 구현 | 새 블록 배치 가능 여부에 따른 종료 로직 | 새 블록의 시작 셀이 이미 점유된 경우 게임 종료 상태가 되고, 입력 및 자동 하강으로 상태가 더 변경되지 않는다는 테스트가 통과한다. |
| 21. 게임 상태 초기화 구현 | 최초 시작 및 재시작에 공통으로 쓰는 초기화 함수 | 호출 시 빈 보드, 새 블록, 0점, 진행 중 상태로 초기화된다는 테스트가 통과한다. 이전 게임의 보드 데이터가 남지 않는다. |
| 22. 게임 보드 렌더링 구현 | 상태를 화면의 10 × 20 셀로 표현하는 렌더러 | 고정 블록과 현재 블록이 서로 구분되어 올바른 위치와 종류별 색상으로 표시되며, 렌더링이 게임 상태를 직접 변경하지 않는다. |
| 23. 점수와 Game Over UI 구현 | 점수 표시 및 게임 종료 메시지 | 상태 변경 후 점수가 즉시 갱신되고, 종료 상태에서 Game Over 메시지가 표시되며 진행 중에는 숨겨진다. |
| 24. 키보드 좌우 이동 연결 | 좌우 방향키 입력 처리 | 왼쪽/오른쪽 방향키를 한 번 누를 때 블록 이동이 한 번 시도되고 화면이 즉시 갱신된다. 게임 종료 후에는 입력이 무시된다. |
| 25. 키보드 회전 연결 | 회전 키 입력 처리 | 지정된 회전 키를 누르면 회전이 한 번 시도되고 유효한 결과가 즉시 화면에 반영된다. |
| 26. Soft Drop 입력 연결 | 아래 방향키 입력 처리 | 아래 방향키를 누를 때 블록이 즉시 한 칸 하강하며, 더 내려갈 수 없으면 정상적인 고정·다음 블록 전환 흐름이 실행된다. |
| 27. 자동 하강 타이머 구현 | 일정 간격으로 게임을 진행하는 루프 | 게임 진행 중 블록이 설정된 간격마다 한 칸 하강하고, 중복 타이머 없이 시작·정지할 수 있다. Game Over 시 타이머가 정지한다. |
| 28. Restart 버튼 연결 | 전체 게임을 다시 시작하는 UI 동작 | Restart 클릭 시 기존 타이머가 제거되고 보드, 현재 블록, 점수, Game Over 표시가 초기화되며 새 타이머가 하나만 시작된다. |
| 29. 핵심 게임 흐름 통합 테스트 | 생성부터 Game Over까지의 시나리오 테스트 | 블록 생성→이동/회전→하강→고정→라인 제거→점수 증가→새 블록 생성 흐름과 Game Over 및 Restart 시나리오가 자동 테스트로 통과한다. |
| 30. 데스크톱 브라우저 수동 검증 | 브라우저별 MVP 점검 결과 | 지원 대상 데스크톱 브라우저에서 보드 표시, 키 입력 반응, 자동 하강, 점수, Game Over, Restart를 점검해 치명적 오류가 없다. |
| 31. PRD 성공 기준 최종 확인 | 완료 체크리스트 및 문서 갱신 | PRD의 F1~F12와 성공 기준이 모두 구현·검증되었고, 실행 방법과 조작 키가 README에 명시되어 있다. |

## 구현 시 유지할 원칙

- 게임 규칙과 상태 변경은 화면 조작 코드와 분리한다.
- 핵심 로직 함수는 타이머나 DOM 없이 테스트할 수 있게 작성한다.
- 키보드 입력과 타이머는 게임 로직을 직접 복제하지 않고 상태 변경 함수를 호출한다.
- Hold, Ghost Piece, 모바일 터치, 사운드 등 PRD의 범위 제외 기능은 MVP 완료 전 추가하지 않는다.
